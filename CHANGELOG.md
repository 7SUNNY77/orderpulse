# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [SemVer](https://semver.org/lang/ru/).

## [1.0.0] — 2026-10-13

Первый публичный релиз.

### Реализовано

- **Данные:** загрузка девяти CSV Olist без изменения исходников, аудит качества (`reports/data_quality.md`),
  DuckDB-витрины raw → staging → marts с одной строкой на заказ в `mart_orders`, 17 проверок сверки,
  атомарная и идемпотентная пересборка.
- **ML:** 28 признаков на момент `order_approved_at` из явного allow-list; временные выборки train / validation /
  test с месячными зазорами; кодовая проверка доступности меток (`assert_labels_available`); модели — константа,
  правило «короткий срок», Logistic Regression (основная), CatBoost (сравнение).
- **Очередь риска:** top-K в каждый день подтверждения (K = 20 по умолчанию), фильтры до выбора top-K,
  детерминированный порядок при равных скорах, CSV-экспорт видимой таблицы, исходы скрыты по умолчанию.
- **Объяснения:** для Logistic Regression — «Вклады признаков в линейный скор» (свободный член + Σвкладов =
  decision_function, агрегация до исходных признаков); для CatBoost — SHAP.
- **Оценка:** Precision/Recall@K (micro/macro), аналитический и Monte Carlo случайный baseline, K-кривые,
  парный bootstrap по дням и неделям, календарные ablation, проверка калибровки, аудит конца датасета
  (`reports/reliability_report.md`, `reports/dataset_tail_audit.md`).
- **Приложение:** пять страниц на русском — обзор, сегменты, очередь, карточка заказа, качество модели и данных.
- **Лицензия:** код — MIT; данные Olist — отдельно, CC BY-NC-SA 4.0.
- **Упаковка:** версия пакета 1.0.0, CLI `python -m orderpulse`, закреплённые версии в `requirements-lock.txt`,
  понятные сообщения CLI при отсутствии CSV, базы или артефактов, workflow GitHub Actions на синтетических данных.

### Проверки

- `python -m pytest`: 85 тестов на синтетических данных; маркер `integration` выделяет синтетический pipeline
  и страницы Streamlit AppTest.
- Полный pipeline на наборе Olist, 17/17 проверок витрин; браузерный сценарий 11 из 12 шагов.
- Установка из публикуемых файлов в новое окружение.

### Главный результат

Три ретроспективных development-окна, K = 20 в день: Logistic Regression — precision 17,13%, lift 1,773,
3,412 найденной задержки в день против 1,925 при случайном отборе.

### Известные ограничения

- Историческая симуляция; модель обучена только на доставленных заказах.
- Риск-скор не откалиброван; найденная задержка не означает предотвращённую.
- Development-результат относится к backtest-моделям по тому же рецепту; исходный test ранее просмотрен.
- Механизм отбора в конце датасета неизвестен; июль–август 2018 не используются для оценки.
- Диапазон дат и фильтры очереди сбрасываются при переходе между страницами.
